## Contract criteria quoted

- PRD-001 §3, H1 row: precondition is "server fails `check` 3 consecutive times"; effect "comment out its registration, keep the entry in a `quarantined[]` block".
- PRD-001 §4 non-goals: "No OAuth automation, no credential storage, no secret values in any output or receipt"; "No silent removal of a server a human registered"; "No model call inside `heal`. Every repair must be deterministic and reproducible offline."
- PRD-001 §5 criterion 1: `--plan` reports exactly one H1 repair and writes nothing (directory hash unchanged).
- PRD-001 §5 criterion 2: `--apply` changes exactly one entry, writes one receipt under `.mcp-doctor/heal/<id>.json`, leaves the rest byte-identical.
- PRD-001 §5 criterion 3: `--rollback <id>` restores byte-identical pre-image (sha256 equality asserted).
- PRD-001 §5 criterion 6: inline secret rewritten to `${env:...}`, "the receipt's diff redacts it".
- PRD-001 §5 criterion 8: `--apply` twice is idempotent (second run zero repairs, no receipt).
- PRD-001 §5 criterion 9: `score` runs before/after under PRD-004's two scales, receipt records both; "a repair that raises `quality` while lowering `conformance` is a failure, not a success, and the receipt says so".
- PRD-001 §5 criterion 10: exit codes 0/1/2/3/4.
- PRD-001 §6: S1 = `src/heal/{plan,apply,rollback}.ts` + H1 only, done when criteria 1, 2, 3, 8 pass.
- PRD-004 §1: a blended score is "unfalsifiable"; §7: "`heal` acts on what `score` says. Healing to raise a number that measures the wrong thing is worse than doing nothing." This is why criterion 9 is worded as a failure guard: a rising `quality` number (a private estate bar, PRD-004 R1) must not be allowed to mask a `conformance` regression. A green metric is not proof of correctness, which is the standard applied below. The S1 receipt carries no `conformance`, `quality`, `revision` or `criteriaVersion` fields, so criterion 9 is unaddressed in this slice (consistent with §6 S1 scope); no verdict is rendered on it here.

## Task 2: risk table

| Surface | Scenario | Prevented? | Required change |

| A. H1 precondition strength | `plan.ts:27,84-124`: `FAILURES_REQUIRED = 3` is consumed as three back-to-back `checkServerHealth` calls inside one `evaluateEntry` invocation (lines 98, 111-117), each with `PROBE_TIMEOUT_MS = 3000`. The comment at lines 108-109 states it retries "rather than persisting state, because --plan must never write anything". So "3" counts three probe attempts within a single run, with no history across invocations and no time separation. A healthy-but-slow server, or one hit by a transient blip that spans the three probes, is classified `dead` and moved to `quarantined[]`; a working server disappears from the user's config. `--apply` re-runs the three probes from scratch (`apply.ts:111` calls `planFromText`), so a plan and apply can disagree on the same config. | NO | Precondition must mean 3 consecutive failed checks across separate invocations over time, persisted durably keyed by (server identity + config hash), incremented once per distinct check run, reset on any success, with a minimum interval between counted failures. Because §4 forbids `--plan` writing, the count must be recorded out of band by the existing `check`/`audit` command (which §1 already runs on a schedule) into a durable store; `--plan` and `--apply` read that store and quarantine only at count >= 3. This also makes plan and apply consistent. |
| B. ## Verdict

DO NOT SHIP. All four assigned criteria are genuinely met on their fixture, but four independent risk surfaces (A, B, C, D) are unaddressed, including a healthy-server data-loss defect, a plaintext-credential receipt that contradicts §4 and criterion 3, an invalid-JSON splice on a legitimate config, and unrecoverable config states. No single change clears all four. The highest-leverage single change is B: stop storing the byte-exact pre-image (and its secrets) in the receipt and reconstruct it at rollback from `quarantined[]` (or a permissioned, gitignored store), resolving the §4 vs §5.3 conflict; A, C and D still require their own fixes before merge.
